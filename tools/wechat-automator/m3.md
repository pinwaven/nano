# WeChat DevTools on M3 from us1

M3 is the default WeChat DevTools host when working on `us1.gcn.net`, as requested
2026-10-07. Build xapp-mini on us1 and run its simulator tests on M3. Use i9/m4 when the
user requests them or a specific device/parity task needs them.

## Access

```bash
ssh -o ConnectTimeout=10 m3 hostname
```

us1's SSH alias `m3` connects to `127.0.0.1:2224` as `pin`, using
`~/.ssh/us1_to_m3`, `IdentitiesOnly yes`, `BatchMode yes`, and `HostKeyAlias m3`.
The permanent reverse tunnel runs from M3 to us1; M3 must be awake and online.
Ports `2222` and `2223` belong to i9 and m4 respectively.

M3 has DevTools at `/Applications/wechatwebdevtools.app`, the repo at
`/Users/pin/waven/nano`, and Node available through `zsh -lic`. M3 has no passwordless sudo.
Attach to the user's existing, signed-in DevTools instance. If necessary, ask the user to
open DevTools from the Dock and sign in with the QR code; avoid a cold start over SSH.

## Build, sync and attach

Run from `/home/pin/waven/nano` on us1:

```bash
APPID=wxecbcf00ce480fcf2 tools/xapp-mini/build.sh
rsync -a --delete --exclude project.private.config.json \
  dist/xapp/mini/ m3:waven/nano/dist/xapp/mini/
ssh m3 '/Applications/wechatwebdevtools.app/Contents/MacOS/cli auto --project /Users/pin/waven/nano/dist/xapp/mini --auto-port 22091 --port 22038'
```

The M3 project is `~/waven/nano/dist/xapp/mini`, not `src/xapp` or the production miniapp.
`dist/xapp/mini` is git-ignored: rebuild and sync every source change. Preserve DevTools'
`project.private.config.json`. Keep `setting.es6: true`, `setting.swc: false` and
`setting.disableSWC: true`, as generated by `build.sh`. SWC conversion caused
`ReferenceError: C is not defined` on startup. Legacy Babel conversion was verified in
build `1007-4`: all four tabs load without runtime errors and preview succeeds (1,805,222
bytes). Close/reopen the project after changing these settings; the running page's method
source shows `_regeneratorRuntime` after Babel conversion.

`22038` is the CLI HTTP service port. `22091` is the xapp-mini automation websocket port.
They are separate. If automation is already active, use the helper's `connect(22091)`.
Its `launch()` has a fixed production-miniapp project path, so use the CLI command above
to enable automation for xapp-mini. If the CLI reports a port conflict, try connecting first.

DevTools' `develop` environment uses `https://nano-dev.gcn.net`. Uploaded trial/release builds
use production. Verify the backend and displayed VERSION before a test. Use the project's
configured appid when building. **Do not Upload** with this shared appid: it replaces the
production miniapp's development version.

## Run a test script

Write one-off scripts under us1's `temp/`, copy them to M3, then run Node there:

```bash
scp temp/<test>.cjs m3:/tmp/nano-devtools-test.cjs
ssh m3 'zsh -lic "node /tmp/nano-devtools-test.cjs"'
```

Use the existing helper on M3:

```js
const { connect } = require(process.env.HOME + '/waven/nano/tools/wechat-automator/connect');
let mp;
try {
  mp = await connect(22091);
  const identity = await mp.evaluate(() => {
    const page = getCurrentPages().slice(-1)[0];
    const vm = page.$vm;
    return {
      path: page.route,
      nickname: vm.user?.getString('nickname'),
      userId: vm.user?.getString('user_id'),
      version: vm.version,
      base: wx.getStorageSync('nano_base'),
      env: wx.getAccountInfoSync().miniProgram.envVersion,
    };
  });
  console.log(identity);
} catch (error) {
  console.error(error.message);
  process.exitCode = 1;
} finally {
  if (mp) await mp.disconnect();
}
```

Put that snippet inside an async function in a `.cjs` script. xapp-mini page methods live on
`getCurrentPages()[n].$vm`; for example, `vm.switchTab('health')`. Health component state lives
on `vm.$refs.healthComp`; `subAgeList` does not live on the page. Real tab taps through
`page.$$('.tab-btn')` worked on M3. Read typed users with `getString()`.

Storage persists across launches. Verify the requested user before testing; Pin's dev
`user_id` is `37c8774e`. Use the supported phone/super-OTP sign-in when needed, with the
authorized credential from the session or environment. Do not put OTPs, phone numbers or
session tokens in documentation or reports. The phone-OTP endpoint takes the 11-digit domestic
phone number, without `+86`.

`reLaunch` reruns page hooks, not `App.onLaunch`. If a test must inject a session, plain objects
are not a substitute for `UTSJSONObject` in live xapp state. Prefer normal sign-in. After a
recompile, confirm the account and backend again.

## Console errors and screenshots

Monitor both `mp.on('console', ...)` and `mp.on('exception', ...)`. An Error argument can be
serialized as `{}` by the console bridge. To capture its actual message and stack, register
`wx.onUnhandledRejection` and `wx.onError` inside `mp.evaluate()` before re-launching the page.
Read `event.reason.message` and `event.reason.stack` for rejections. Remove those listeners
with `wx.offUnhandledRejection`/`wx.offError` after the test. A tab rendering successfully
does not mean the run is free of startup errors.

Window screenshots work on M3:

```bash
ssh m3 '~/.local/bin/winid'
ssh m3 'screencapture -x -o -l <current-window-id> /tmp/nano-devtools.png'
scp m3:/tmp/nano-devtools.png temp/<test-screenshot>.png
```

Find the current `Wechat Devtools` / `xapp-mini` window id each time; reopening the project
changes it. `mp.screenshot()` can fail. Use DOM/state assertions for verification and a
window capture to inspect the visible console. Existing WXSS/preload warnings are separate
from red errors; record any errors rather than reporting an unqualified pass.

## Tunnel recovery

On us1, check `ss -ltn sport = :2224` and retry `ssh -o ConnectTimeout=10 m3 hostname`.
A stale tunnel may take about 90 seconds to clear before autossh reconnects.

If the tunnel stays down, ask the user to run this on M3:

```bash
launchctl kickstart -k gui/$(id -u)/com.pin.reverse-ssh-tunnel-us1
```

The user LaunchAgent is `~/Library/LaunchAgents/com.pin.reverse-ssh-tunnel-us1.plist`.
Logs are `~/Library/Logs/reverse-ssh-tunnel-us1.err.log` and
`~/Library/Logs/reverse-ssh-tunnel-us1.out.log`.
