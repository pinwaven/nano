# xapp Android APK

`build.sh` packages `src/xapp` with HBuilderX and copies the new APK to
`dist/xapp/android/` (Git-ignored). HBuilderX keeps compile/cache files in
`src/xapp/unpackage/`.

```bash
tools/xapp-android/build.sh
# Equivalent npm entry point: npm run build:xapp:android
# Or: HBX=/path/to/HBuilderX tools/xapp-android/build.sh
```

Before running it, set a registered DCloud `appid` in `src/xapp/manifest.json`,
sign in to DCloud through HBuilderX, and configure a cloud Android certificate
for that app. The current manifest has an empty `appid`, so packaging stops at
the preflight check. HBuilderX's `pack` command submits an Android package job;
the script copies only an APK generated by that invocation. It does not upload
the APK to an app store or deploy it.

For a compile check without APK packaging, continue using
`HBuilderX/cli launch app-android --project src/xapp --compile true`.
The native `BUILD_ENV` in `src/xapp/utils/config.uts` currently points to the
dev backend; switch and test it before making a production release build.
